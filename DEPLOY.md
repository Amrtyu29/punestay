# Putting PuneStay online for free

One container runs everything the site needs: the FastAPI server serves the home page at `/`, the React app at
`/app/`, the API behind `/api/`, and listing photos at `/uploads/`. The database lives in Neon (hosted PostgreSQL
with PostGIS). Both services have free plans with no card required.

| Piece | Where | Free plan limits that matter |
| --- | --- | --- |
| Database (PostGIS) | [Neon](https://neon.tech) | 0.5 GB storage (the PuneStay database is 33 MB), sleeps when idle and wakes in about a second |
| API + pages | [Render](https://render.com) web service, Docker | sleeps after 15 min without visitors, the first visit then takes 30 to 60 s; the disk is wiped on every deploy, so uploaded photos do not survive a redeploy |
| Routing | public OSRM demo server | already the fallback when no local OSRM runs; demo use only |
| Basemaps and geocoding | OpenFreeMap, OSM, Esri, Nominatim | unchanged, all key-free |
| GeoServer WMS overlays | optional, see the end | not part of the free setup; the page works without them |

Everything below is done once. After that, every `git push` to `main` redeploys the site automatically.

## 1. The database on Neon (done on 2026-10-28)

The Neon project `odd-fog-82975793` (Singapore, PostgreSQL 18, PostGIS 3.6) holds the data. It was set up with
the Neon CLI, which linked this folder to the project (`.neon`, `neon.ts`) and wrote three variables into `.env`:
`DATABASE_URL` (pooled, for the app), `DATABASE_URL_UNPOOLED` (direct, for dumps and restores) and
`NEON_BRANCH`. `.env` is not committed. To redo the link on another machine:

```bash
npm i -g neon@latest ; neon login ; neon init -y --org-id org-sweet-cell-31632046 --project-id odd-fog-82975793 --branch production --services postgres ; neon deploy
```

With `DATABASE_URL` present the API uses Neon even on the laptop. Remove or comment out that line in `.env` to
go back to the portable PostgreSQL on port 5433.

## 2. Copy the local data to Neon (done, repeat whenever the laptop data changes)

The local database must be running (`scripts\pg_start.ps1`). Use the **unpooled** URL from `.env`:

```bash
powershell -ExecutionPolicy Bypass -File scripts\migrate_to_cloud.ps1 -Url "<DATABASE_URL_UNPOOLED from .env>"
```

The script dumps the local database, creates the PostGIS and pg_trgm extensions on Neon, restores everything
(listings, POIs, destinations, rent observations, users, the `listings_public` view) and prints the row counts on
both sides. They must match. Your local accounts, including the admin account, are copied with their passwords,
so the same sign-in works online. Note that it replaces the Neon tables, so listings added online since the last
copy are lost: once the site is live, treat Neon as the main database.

## 3. Deploy on Render

1. Sign up at https://render.com with your GitHub account and allow it to see the `Amrtyu29/punestay` repository.
2. Click **New > Blueprint**, choose the repository. Render reads `render.yaml` and shows one web service named
   `punestay` on the free plan.
3. It asks for the two values that are not in the file:
   - `DATABASE_URL`: the pooled Neon connection string, the `DATABASE_URL` line of `.env` (without the quotes).
   - `ADMIN_EMAIL`: the email of the admin account (the one you registered locally; it was copied in step 2).
4. Click **Apply**. The first build takes 5 to 10 minutes (it installs the front-end packages, builds the pages,
   installs Python). When the log shows `Application startup complete` the site is at
   `https://punestay.onrender.com` (if the name was taken, Render adds a suffix; then open the service's
   **Environment** tab and change `CORS_ORIGINS` to the real URL).
5. Open `https://<your-service>.onrender.com/health`: it must say `"database": true`.

`JWT_SECRET` and `ADMIN_SETUP_TOKEN` are generated by Render. The setup token is only needed if you ever register
the admin account afresh online (registration body field `admin_token`); copy it from the **Environment** tab.

## 4. Check the site

- `/` home page: the intro shows the live counts (520 places), a scan returns PGs and hostels, Details opens in
  the panel, Sign in works with your local account, Add a PG saves a listing.
- `/app/` React app: listings in the map view, directions, compare areas.
- `/docs`: the API documentation.

## Updating later

Push to `main` and Render rebuilds the image and redeploys. Data changes (new listings, accounts) live in Neon
and are not affected by a redeploy. To refresh the database from the laptop again, rerun step 2: the script
replaces the tables on Neon with the local ones.

## Optional: GeoServer overlays online

The WMS layers (all listings, PG, hostel, bus and metro stops) come from GeoServer, which the free Render service
does not run. The page simply works without them. If you want them online, run GeoServer somewhere reachable
(for example a Docker Space on Hugging Face with the `kartoza/geoserver` image, pointed at Neon) and tell the
page where it is by adding, in `frontend/index.html` before `js/app.js`:

```html
<script>window.PUNESTAY_GEOSERVER = 'https://your-geoserver.example/geoserver';</script>
```

For a one-off demo the same can be passed as `?geoserver=https://...` in the page URL.

## Running the container locally (when Docker is available)

```bash
docker build -t punestay . ; docker run -p 8000:8000 -e DATABASE_URL="postgresql://..." punestay
```

Without Docker the same thing is tested by building the front end (`npm run build` in `frontend`) and starting
the API: it serves `frontend/dist` whenever that folder exists.
